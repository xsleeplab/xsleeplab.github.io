# 被试报名通知云函数（腾讯云 SCF）

`signup/` 报名表单提交后，数据发到这个云函数，由它转发飞书群通知。

## 为什么需要它

飞书 webhook 如果写在前端 JS 里就是公开的，任何人查看源码即可拿去往实验室群灌消息。
放到云函数之后：

- **webhook 只存在于环境变量**，前端代码里不再出现
- **卡片由函数按固定结构拼装**，调用方只能提交结构化数据，无法控制消息形态
- **数据落在腾讯云北京节点**，被试的敏感健康信息不出境
- 附带 IP 频率限制与来源白名单

## 部署步骤

### 1. 创建函数

腾讯云控制台 → [云函数](https://console.cloud.tencent.com/scf) → 地域选 **北京** → 新建

| 项 | 值 |
|---|---|
| 创建方式 | 从头开始 |
| 函数类型 | 事件函数 |
| 函数名称 | `xsleep-notify` |
| 运行环境 | **Node.js 18** |
| 执行方法 | `index.main_handler`（默认） |

> API 网关触发器已于 2025-06-30 下线，**不要配置任何触发器**，改用下面的函数 URL。

### 2. 粘贴代码

把 `index.js` 的内容贴进在线编辑器并部署。函数不依赖任何 npm 包，只用 Node 内置的
`https` 与 `url`。

### 3. 配置环境变量

函数配置 → 环境变量：

| 键 | 值 |
|---|---|
| `FEISHU_WEBHOOK` | 飞书群机器人的完整 webhook 地址 |

⚠️ 这是唯一存放 webhook 的地方。**不要**把它写回前端。

### 4. 开启函数 URL

函数管理 → 函数配置 → 编辑 → 函数 URL：

- 启用：**开**
- 鉴权方式：**免鉴权**
- 若有请求方法选项：勾选 **POST 与 OPTIONS**（浏览器预检需要 OPTIONS）

保存后复制生成的地址，填到 `signup/index.html` 的 `SUBMIT_ENDPOINT`。

## 允许的来源

`index.js` 中的 `ALLOWED_ORIGINS` 硬编码了三个来源：

```
https://xsleeplab.cn
https://www.xsleeplab.cn
https://xsleeplab.github.io
```

换域名时记得同步修改，否则浏览器会因 CORS 被拒。

## 返回约定

| 状态码 | 含义 |
|---|---|
| `200 {ok:true}` | 已送达飞书 |
| `400` | JSON 无效或缺少 name/email |
| `403` | 来源不在白名单 |
| `429` | 同一 IP 一小时内超过 5 次 |
| `500` | 未配置 `FEISHU_WEBHOOK` |
| `502` | 飞书转发失败 |

前端只在收到 `200 {ok:true}` 时才告诉被试"提交成功"，其余一律如实报错并提供邮箱兜底。

## 频率限制的边界

限流计数存在函数实例的内存里。SCF 会复用实例但**不保证常驻**，实例回收后计数清零，
因此这是一道减速带而非强保证。若将来需要严格限流，改用云数据库或 Redis 记录。

## 本地验证

仓库外有一套针对本函数的测试（打桩 `https.request`，不发真实请求），覆盖：
CORS 预检、来源白名单、字段校验、卡片结构、超长/控制字符净化、限流、
飞书非零 code、网络异常、base64 请求体、新旧两种事件格式。
