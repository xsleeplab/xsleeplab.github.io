# 被试报名通知云函数（腾讯云 SCF）

`signup/` 报名表单提交后，数据发到这个云函数，由它转发飞书群通知。

## 为什么需要它

飞书 webhook 如果写在前端 JS 里就是公开的，任何人查看源码即可拿去往实验室群灌消息。
放到云函数之后：

- **webhook 只存在于环境变量**，前端代码里不再出现
- **卡片由函数按固定结构拼装**，调用方只能提交结构化数据，无法控制消息形态
- **数据落在腾讯云北京节点**，被试的敏感健康信息不出境
- 附带 IP 频率限制与来源白名单

## 部署步骤

### 1. 创建函数

腾讯云控制台 → [云函数](https://console.cloud.tencent.com/scf) → 地域选 **北京** → 新建

| 项 | 值 |
|---|---|
| 创建方式 | 从头开始 |
| 函数类型 | 事件函数 |
| 函数名称 | `xsleep-notify` |
| 运行环境 | **Node.js 18** |
| 执行方法 | `index.main_handler`（默认） |
| **执行超时时间** | **60 秒**（默认 3 秒、旧版 15 秒和 30 秒都不够） |

> 带预约的提交在冷启动时可能依次经历取 tenant_access_token、最多 6 页时段查询、
> 写入预约、回读确认，再并行归档与发送飞书卡片；最坏链路约 40 秒，需保留余量。
> 平台超时的表现是 HTTP 433
> `Invoking task timed out`，而不是任何业务错误码。

> API 网关触发器已于 2025-06-30 下线，**不要配置任何触发器**，改用下面的函数 URL。

### 2. 粘贴代码

把 `index.js` 的内容贴进在线编辑器并部署。函数不依赖任何 npm 包，只用 Node 内置的
`https` 与 `url`。

### 3. 配置环境变量

函数配置 → 环境变量：

| 键 | 必填 | 值 |
|---|---|---|
| `FEISHU_WEBHOOK` | ✅ | 飞书群机器人的完整 webhook 地址 |
| `FEISHU_APP_ID` | | 自建应用的 App ID（`cli_` 开头） |
| `FEISHU_APP_SECRET` | | 自建应用的 App Secret |
| `BITABLE_APP_TOKEN` | | 多维表格地址里 `/base/` 后面那段 |
| `BITABLE_TABLE_ID` | | 报名记录表的 table_id（地址里 `table=` 后面那段） |
| `BITABLE_SLOT_TABLE_ID` | | 时段表的 table_id（同一个多维表格里的第二张数据表） |

⚠️ `FEISHU_WEBHOOK` 是唯一存放 webhook 的地方，**不要**把它写回前端。

后四项用于把报名归档到多维表格，缺任意一项则跳过归档、只发飞书卡片。

### 3b. 多维表格归档

每份报名会追加成表格的一行，供筛选、排序、导出 Excel。

**必须先在表格里建好这些列，列名要完全一致**，否则飞书会整行拒绝：

| 列名 | 类型 |
|---|---|
| 姓名（首列） | 文本 |
| 提交时间 · 结果 · 手机 · 邮箱 · 报名项目 · 中止原因 | 文本 |
| 年龄 · PSQI · ISI · rMEQ · DASS抑郁 · DASS焦虑 · DASS压力 | 数字 |
| 昼夜类型 · 视力 · 环境适应 · 三个月内染发 | 文本 |
| 可用日期 · 时间灵活度 · 最早可参与 · 备注 | 文本 |

除了开通 `bitable:app` 权限并发布应用，还**必须把应用加进这张表格**：
表格右上角「⋯」→「更多」→「添加文档应用」→ 选择应用 → 权限设为可编辑。
漏掉这步会报 `91403 Forbidden`。

归档是尽力而为：写表失败不会让被试提交失败，但会记进函数日志，
并在响应里返回 `archived: "failed"`。`"skipped"` 表示未配置，`"ok"` 表示成功。

> 表格里的**空行也是真实记录**。新建的多维表格自带几行空记录，
> 新增记录永远追加在最后一条之后，所以写入会从空行下方开始。
> 把空行删掉一次即可，之后就是连续的。

### 3c. 预约时段

在**同一个多维表格里新建第二张数据表**（如「时段」），列如下：

| 列名 | 类型 |
|---|---|
| 时段ID（首列） | 文本 |
| **日期** | **日期** ← 必须是日期类型，日历视图才能用 |
| 星期 · 实验室 | 文本 |
| 状态 | 单选：可预约 / 已预约 / 关闭 |
| 预约人 · 预约邮箱 · 预约项目 · 预约时间 | 文本 |

建好后给这张表加一个**日历视图**（视图栏「+」→ 日历），按「日期」分组，
主试就能在月历上直接看排期、点进某天把状态改成「关闭」。

被试端**不使用**这个视图——那需要公开分享表格，会暴露其他被试的
姓名与邮箱。被试看到的是网站上的日历，数据来自只回可用性的接口。

**不需要手工建行**：被试第一次打开合格页时，函数会自动补齐未来 28 天
× 2 间实验室的全部格子。之后每天窗口前移，也只补新增的那天。

主试要停用某个时段，把该行的「状态」改成 **关闭** 即可，前端会置灰。

给被试的时段接口只返回 `日期 / 星期 / 实验室 / 状态`，
**预约人与邮箱在函数内部就被丢弃**——不是靠前端隐藏，数据根本不出服务端。

并发限制：多维表格没有唯一约束，函数采用「写前检查 + 写后回读」压缩撞单
窗口；回读必须精确匹配状态、姓名和邮箱，否则拒绝确认。但 A 回读后仍可能被 B
覆盖，所以响应只标记 `bookingStatus: "pending"`，必须由实验室最终确认。若需即时
确定预约，必须迁移到支持条件写入或唯一约束的原子存储。

### 4. 开启函数 URL

函数管理 → 函数配置 → 编辑 → 函数 URL：

- 启用：**开**
- 鉴权方式：**免鉴权**
- 若有请求方法选项：勾选 **POST 与 OPTIONS**（浏览器预检需要 OPTIONS）

保存后复制生成的地址，填到 `signup/index.html` 的 `SUBMIT_ENDPOINT`。

## 允许的来源

`index.js` 中的 `ALLOWED_ORIGINS` 硬编码了三个来源：

```
https://xsleeplab.cn
https://www.xsleeplab.cn
https://xsleeplab.github.io
```

换域名时记得同步修改，否则浏览器会因 CORS 被拒。

## 返回约定

| 状态码 | 含义 |
|---|---|
| `200 {ok:true}` | 报名已送达；无时段请求时可直接显示提交成功 |
| `200 {ok:true, booking, bookingStatus:"pending"}` | 时段写入后已回读匹配，但因表格无原子锁，仍等待实验室最终确认 |
| `200 {ok:true, notification:"failed"}` | 时段请求已记录或报名已归档，但飞书通知延迟；前端提示无需重试 |
| `400` | JSON 无效或缺少 name/email |
| `403` | 来源不在白名单 |
| `429` | 同一 IP 一小时内报名超过 5 次，或查询时段超过 60 次 |
| `500` | 未配置 `FEISHU_WEBHOOK` |
| `502` | 尚未确认预约时，飞书转发失败 |

前端会核对响应中的时段与状态；当前 Bitable 实现只返回 `pending`，页面明确提示
“等待实验室最终确认”。只有未来原子预约服务明确返回 `confirmed` 时才会显示预约成功。
报名已送达但时段未确认、或时段/归档写入后通知延迟时，也不会要求重复提交。

## 频率限制的边界

报名和只读时段查询分别计数，避免正常查看日历耗尽报名额度。限流计数存在函数实例的内存里。SCF 会复用实例但**不保证常驻**，实例回收后计数清零，
因此这是一道减速带而非强保证。若将来需要严格限流，改用云数据库或 Redis 记录。

## 本地验证

仓库内 `tests/scf-handler.test.mjs` 会打桩 `https.request`，不发真实请求，覆盖：
未确认预约不能进入归档/通知、预约成功后的通知失败、时段查询与报名限流隔离。
运行仓库根目录 README 中的完整测试命令即可一并验证。
