# X-Sleep Lab 网站均衡优化设计

**日期：** 2026-07-11
**状态：** 已选定 B 方案，待作者审阅书面设计
**目标：** 在不改变实验室事实内容、招聘政策、莫兰迪视觉和纯静态部署方式的前提下，修复已确认的问题，并提升加载性能、搜索可见性、可访问性和长期维护性。

## 1. 范围与边界

本轮包含以下工作：

1. 修复缺失翻译字段导致的可见文案被清空问题。
2. 修正参与者页面的旧 Open Graph URL、地址错字与页面语言声明。
3. 将当前实际使用的大图转为更小的 WebP 版本，并补充尺寸与懒加载策略。
4. 让论文、新闻和团队成员的核心内容直接存在于最终 HTML 中，在 JavaScript 不运行时仍可阅读和索引。
5. 补齐 favicon、canonical、基础 robots/sitemap、页面级 Open Graph 信息和实验室结构化数据。
6. 增加键盘焦点、当前页面语义、减弱动画支持和移动菜单基础键盘行为。
7. 合并重复的前端渲染实现，保留一个明确的数据源与一个运行时渲染入口。

本轮明确不做：

- 不更改论文题目、作者、期刊、DOI、人员、职位状态或伦理政策事实。
- 不重新设计配色、Logo、导航结构或页面信息架构。
- 不引入 React、Vue、打包器、数据库或第三方运行时依赖。
- 不删除原始图片；优化版本以新文件保存，避免破坏用户资产。
- 不发布、不推送、不创建提交，除非用户另行授权。

## 2. 总体方案

网站继续作为可直接部署的 HTML/CSS/Vanilla JS 项目。`js/content.js` 保持为论文、新闻和成员数据的单一事实来源；新增一个只依赖 Node.js 内置模块的静态生成脚本，在维护内容后把数据预渲染进对应 HTML 容器。浏览器端 JavaScript 仍负责语言切换和更新内容，但不再承担“首次产生核心内容”的唯一责任。

自动化检查使用 Node.js 内置 `node:test`，不新增 npm 依赖。测试首先覆盖当前已确认的失败症状，再实施修复。

## 3. 双语与内容一致性

### 3.1 缺失翻译

为英文和中文翻译对象补齐以下字段：

- `team.piLabel`
- `research.item3p2`
- `publications.researchGate`

语言更新函数将增加安全保护：当目标翻译值不是字符串时，不覆盖 HTML 中已有的后备文案。这样即使以后漏填翻译，也不会再次把可见内容清空。

### 3.2 首页精选论文

首页第二张轮播统一为 TiCS 2025。HTML 后备文案、英文翻译和中文翻译使用同一事实，不再出现静态 HTML 为 PNAS 2024、运行后又变成 TiCS 2025 的情况。

### 3.3 参与者页面语言

参与者指南本轮继续保持中文单语。该页面始终声明 `lang="zh-CN"`，不受全站已保存语言偏好影响；导航可继续显示用户偏好的语言，但正文语义保持中文。该页面隐藏语言切换控件，避免用户误以为正文能够切换语言。

## 4. 静态内容生成与维护

### 4.1 数据流

```text
js/content.js
    ↓ Node 内置 vm 读取
scripts/render-static-content.mjs
    ↓ 更新带边界标记的容器
publications.html / news.html / team.html / index.html
    ↓ 浏览器加载
lang-switch.js + 单一渲染模块更新当前语言
```

### 4.2 生成边界

生成脚本只改写明确注释标记之间的内容，例如：

```html
<!-- STATIC:PUBLICATIONS:START -->
...生成内容...
<!-- STATIC:PUBLICATIONS:END -->
```

脚本找不到成对标记时立即失败，不静默改写整个文件。生成结果必须可重复运行且无额外 diff。

### 4.3 浏览器渲染逻辑

保留 `js/md-loader.js` 作为唯一渲染实现，并从 `js/content.js` 删除重复函数；`content.js` 只保存数据。空邮箱不生成空的 `mailto:` 链接。图片 HTML 统一输出尺寸、`loading` 与 `decoding` 属性。

## 5. 图片与加载性能

### 5.1 预算

- 首页本地首屏及内容图片总量目标：不超过 2 MiB。
- `dream.png` 的 WebP 替代版本目标：不超过 500 KiB。
- 三张研究方向图每张目标：不超过 200 KiB。
- 新闻与成员图片按展示尺寸缩放，不保存远高于实际展示需求的像素尺寸。

### 5.2 策略

- 保留原图，新增 `.webp` 文件并更新网站引用。
- Hero 图保留立即加载；首屏以下图片使用 `loading="lazy"` 和 `decoding="async"`。
- 所有内容图片提供显式 `width`、`height`，CSS 继续负责响应式缩放。
- Open Graph 图片暂时继续使用兼容性更好的 PNG，不在本轮生成新的品牌视觉。

## 6. SEO 与分享元数据

每个页面补充：

- 正确的 canonical URL。
- 与页面一致的 `og:url`、`og:title`、`og:description`。
- favicon PNG 引用。
- 首页 `Organization`/`ResearchOrganization` JSON-LD，包含名称、网址、机构与联系人等已经公开的信息。

新增：

- `robots.txt`，允许公开抓取并指向 sitemap。
- `sitemap.xml`，列出七个公开页面。

中文和英文目前共用同一 URL 与本地偏好，因此本轮不添加容易误导的 `hreflang`。若未来改为独立 `/zh/` 与 `/en/` 路径，再添加完整 hreflang。

## 7. 可访问性与交互

- 为链接、按钮和菜单控件添加清晰的 `:focus-visible` 样式。
- 当前导航链接增加 `aria-current="page"`。
- 移动菜单支持 Escape 关闭；关闭后焦点返回菜单按钮。
- 菜单按钮增加 `aria-controls`，导航拥有稳定 `id`。
- 在 `prefers-reduced-motion: reduce` 下关闭平滑滚动、卡片位移和自动轮播。
- 首页自动轮播在减弱动画偏好下不启动 autoplay；正常模式保留现有 16 秒节奏。
- 参与者页面复用 `js/nav.js`，删除其单独维护的简化版菜单脚本。

## 8. 错误处理与退化行为

- 缺失翻译值时保留原始 HTML 文案。
- Swiper CDN 不可用时，首页只显示第一张 Hero，其他幻灯片隐藏，页面其余部分仍可使用。
- 静态生成失败时返回非零退出码，并指出缺失的标记或数据字段。
- 图片优化脚本不覆盖原图；输入缺失时失败并列出具体文件。

## 9. 测试与验收

### 9.1 自动化测试

使用 Node.js 内置测试覆盖：

1. 所有 `data-i18n` 使用的关键字段在中英文对象中存在。
2. 未定义翻译不会清空后备文案。
3. 七个页面具有唯一 H1、canonical 和 favicon。
4. 参与者页面 canonical/OG URL 正确且地址统一为“林萃路”。
5. 静态生成后的论文、新闻和成员容器非空。
6. 生成脚本连续运行两次得到相同文件内容。
7. 核心图片引用指向优化版本，且首页图片预算不超过 2 MiB。
8. 当前导航包含 `aria-current`，样式包含 `:focus-visible` 与减弱动画规则。

### 9.2 浏览器验收

在 1440×1000 和 390×844 两个视口检查全部七页：

- 无横向溢出、破图或空白翻译字段。
- 中英文切换后标题和核心文案正确。
- 移动菜单可通过点击、键盘和 Escape 使用。
- 控制台无 favicon 404 和脚本错误。
- 禁用 JavaScript 后，论文、新闻和成员核心内容仍可见。
- 减弱动画模式下无自动轮播和明显位移动画。

## 10. 完成标准

只有在自动化测试全部通过、两种视口浏览器验收完成、图片预算达标、工作区 diff 仅包含本设计范围内文件时，才视为本轮完成。任何无法验证的内容会明确列为遗留项，不以“应该可用”代替证据。
